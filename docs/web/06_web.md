# 第六阶段：轻量购票前端

前端位于 `ticketing/web/`，采用原生 HTML、CSS、JavaScript，直接调用同源 FastAPI 接口。
页面使用蓝色主题，暂不设置品牌名称或 logo。无需 Node 构建、额外前端容器、在线字体或图标库。

## 打开与部署

在已完成第五阶段配置的仓库根目录执行：

```bash
docker compose up -d --build --wait --wait-timeout 120 api
```

浏览器访问 `http://127.0.0.1:8000/`。原有 `/docs` 和 `/openapi.json` 继续可用。
宿主机端口以 `.env` 的 API_PORT 为准，默认 8000。数据库仍只监听本机。
首次部署仍需复制环境示例、启动 PostgreSQL、运行 db-admin 初始化和 demo，完整命令见 README。

## 页面操作

1. 在“发现活动”中按活动名或场馆搜索，并选择某个场次。
2. 查看实际座位和票价，点击可选座位；金额随选择精确汇总。已售或他人占用的座位不可选择。
3. 使用“登录 / 注册”登录或注册新账号。注册密码为 10～128 字符，注册成功后自动登录。
4. 点击“确认下单”，进入“我的订单”，在倒计时结束前选择“去支付”。
5. 确认模拟支付后查看电子票。当前不会发生真实资金扣款。
6. 开场前可以申请整单全额模拟退款，填写原因并确认；原电子票失效，座位重新可售。
7. 待支付订单也可以直接取消。订单可按待支付、已支付、已退款和已关闭筛选。
8. 使用“退出”撤销当前登录令牌，并清空页面上的个人订单信息。

订单详情展示真实活动名称、场馆、开场时间、座位编号、票号和状态历史；活动下架后仍能查看自己的历史订单。
下单、支付和退款的请求 UUID 由页面自动生成，用户不用填写数据库编号或令牌。
库存及订单在页面可见时周期刷新；倒计时仅用于提示，是否可以支付最终由数据库事务判定。

## 登录与错误处理

登录令牌只保留在当前页面内存，不存入 localStorage、sessionStorage 或 Cookie。
刷新或关闭页面后需要重新登录，服务端已有会话仍按一小时有效期管理；主动退出立即撤销当前会话。
账号仍使用第五阶段的 Argon2id 密码哈希和可撤销令牌机制。
前端校验不能代替服务端权限检查，所有订单接口继续从登录令牌识别用户。

请求结果未确认时，同一动作和内容在当前页面复用原 UUID，避免网络重试重复创建支付或退款。
页面刷新会清除内存中的请求编号；若刷新前结果不确定，应先查看自己的订单再继续。
座位竞争、登录过期、数据库或网络不可用时，页面显示可理解的反馈。
注册成功但自动登录未完成时，会切换为登录表单，避免重试注册覆盖已有账号。

金额按“分”使用 BigInt 汇总，避免浮点误差；提交支付仍使用服务器订单价格快照。
活动标题、场馆、用户名、票号等来自接口的文本在进入 HTML 前转义。
静态页面仅允许同源脚本、样式和网络请求，响应设置 CSP 与 nosniff；没有在线脚本依赖。

## 代码分工

| 文件 | 内容 |
|---|---|
| ticketing/web/index.html | 页面结构、表单和对话框 |
| ticketing/web/styles.css | 蓝色主题、桌面及手机适配 |
| ticketing/web/app.js | 接口调用、选座、登录、订单与交互反馈 |
| ticketing/web/lib.mjs | 精确金额、文本转义、请求编号复用与倒计时 |
| ticketing/api.py | 根路径页面、静态资源以及现有 API |
| ticketing/booking.py / schemas.py | 订单展示字段，价格仍使用原快照 |

没有新增数据库迁移，也没有修改旧迁移。静态文件在 Python 包目录内，会随现有 Dockerfile 的 COPY 一并进入镜像。
当前 `codex/web` 基于已完成的 `codex/api` 提交创建，包含尚未合入 main 的 API 功能。
后续合并时需保留这条依赖关系，可先合并 API，再合并前端，或审查整个前端分支中的累计变更。

## 验证

```bash
docker compose run --rm --build tests
```

有 Node.js 的开发电脑还可运行：

```bash
node --check ticketing/web/app.js
node --test tests/js/web.test.mjs
```

Node 仅用于前端开发检查，运行页面和 Docker 部署不需要安装 Node。
浏览器实际验证覆盖登录、选座、下单、支付、电子票、退款、重新购票、取消、筛选、搜索和退出。
记录见 [第六阶段验证](../verification/stage6.md)。
